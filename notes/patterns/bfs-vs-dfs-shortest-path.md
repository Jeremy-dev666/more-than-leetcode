# 为什么无权图最短路径必须用 BFS,而 DFS 注定不行

> 起因:LeetCode 286 (Walls and Gates)。求每个房间到最近门的距离,DFS 写法超时,换成多源 BFS 一遍过。
> 这不是常数优化的差距,而是两种遍历顺序在「求距离」这件事上有本质不同。

## 一句话结论

**BFS 按「距离」扩展,DFS 按「路径」扩展。**
BFS 的访问顺序恰好就是距离从小到大的顺序,所以每个节点**第一次被发现时的距离就是最短距离**,发现即定案,之后永远不用改;DFS 的访问顺序由递归路径决定,第一次到达某个节点时走的往往是一条弯路,想得到正确答案就必须允许反复更新(松弛),而这正是超时的根源。

## BFS 为什么"天然"最短

BFS 用 FIFO 队列,这带来两个不变量(可以对层数归纳证明):

1. **单调性**:队列中节点的距离从队头到队尾非递减;
2. **两层性**:任意时刻队列里最多只有 `d` 和 `d+1` 两种距离的节点。

推理很直接:初始队列里全是距离 0 的源点。弹出一个距离为 `d` 的节点,它产生的新节点距离都是 `d+1`,追加到队尾——队列始终保持「一段 d 后面跟一段 d+1」的形态。于是节点是**严格按距离分层出队**的:所有距离为 `d` 的节点处理完,才轮到 `d+1`。

由此得到关键性质:

> 当节点 `v` 第一次被发现(入队)时,它是被某个距离为 `d` 的节点扩展出来的,所以 `dist(v) = d+1`。这一定是最短的——如果存在更短的路径(长度 ≤ d),那么 `v` 早在处理第 `d-1` 层或更早时就会被发现,与"第一次"矛盾。

这也解释了为什么 BFS 中 `visited` 标记是安全的:第一次发现即最优,后续再碰到直接跳过,**每个节点只入队一次**,总复杂度 O(V + E),网格上就是 O(mn)。

换个视角:BFS 就是**所有边权为 1 的 Dijkstra**。Dijkstra 需要优先队列来保证"每次取出当前距离最小的节点";而当边权全为 1 时,新节点的距离永远等于当前最大距离 +1,普通 FIFO 队列的顺序恰好就是优先队列的顺序——排序是免费送的。

## DFS 为什么错,修对了为什么慢

### 先看"错":第一次到达 ≠ 最短

DFS 沿一条路走到黑。用一个 2x2 网格就能构造反例,`S` 是源点:

```
S A
C B
```

DFS 从 `S` 出发,若先向右再向下,访问顺序是 `S -> A(1) -> B(2) -> C(3)`。
`C` 明明和 `S` 相邻,真实距离是 1,却被记成了 3。如果用了 `visited` 集合,`C` 之后永远不会被修正——**带 visited 的 DFS 求距离,答案直接就是错的**。

### 再看"慢":想修对就必须松弛,复杂度爆炸

要让 DFS 算出正确距离,唯一的办法是放弃 visited,改用**松弛条件**:只有新距离更小时才写入并继续递归:

```python
def dfs(x, y, dist):
    if 越界 or 是墙 or dist >= rooms[x][y]:   # 松弛:不更优就剪枝
        return
    rooms[x][y] = dist
    for 四个方向:
        dfs(nx, ny, dist + 1)
```

这个写法是**正确**的,但每个格子不再只访问一次:每当一条更短的路径迟到,它就要被重新写入,并把更新**级联传播**给整片已经算过的区域。一个格子最坏可能被更新 O(mn) 次(它的距离估计值从很大逐步降到真实值,每降一次都触发一轮扩散),总复杂度最坏达到 **O((mn)^2)**。

对 286 来说,m, n ≤ 250,mn ≈ 62500,平方后约 4×10^9 次操作,再叠加 Python 递归本身的高昂开销——必然超时。而 BFS 是 O(mn) ≈ 6×10^4,差了 5 个数量级。

**本质总结**:BFS 靠访问顺序保证"第一次即最优",把正确性编码进了遍历顺序里;DFS 的顺序不携带任何距离信息,只能靠事后反复修正来补救,正确性和效率不可兼得。

## 286 的多源 BFS:两个额外的点

### 多源 = 虚拟超级源点

把所有门(距离 0)一次性全部入队,等价于凭空造一个"超级源点",向每扇门连一条零权边,然后从它做单源 BFS。分层性质完全不受影响:第 0 层是所有门,第 1 层是所有与任意门相邻的房间……每个房间第一次被触达时,触达它的必然是**离它最近的那扇门**的波前。

对比逐个房间(或逐扇门)做单源 BFS 的 O(k·mn),多源 BFS 把所有源的"波"合并成一次泛洪,整体仍是 O(mn)。**"多个起点求最近距离"是多源 BFS 最典型的触发信号**(同类题:542 01 Matrix、994 Rotting Oranges、1162 As Far from Land as Possible)。

### `rooms[nx][ny] == INF` 一石二鸟

```python
if 0 <= nx < m and 0 <= ny < n and rooms[nx][ny] == INF:
    rooms[nx][ny] = rooms[x][y] + 1
    q.append((nx, ny))
```

这一个判断同时完成了三件事:排除墙(-1)、排除门(0)、充当 visited(已赋值的房间不再是 INF)。能这么省,前提正是 BFS 的"第一次即最优"——写入一次后永远不需要更新,距离数组本身就是 visited 数组。

## 一个必须知道的坑:入队时标记,不是出队时标记

visited(或本题的距离写入)必须发生在**入队时**,而不是出队时。如果等到出队才标记,同一个节点在被处理前可能被多个邻居重复塞进队列,网格上会导致队列膨胀、复杂度退化(最坏从 O(mn) 退到接近 O((mn)^2),和 DFS 松弛殊途同归地慢)。上面代码里"先写距离、再入队"的顺序就是在做这件事。

## 选型速查

| 问题特征 | 正确工具 | 原因 |
|---|---|---|
| 无权图(边权全相等)最短路 / 最少步数 | BFS | 分层扩展,第一次即最优 |
| 多个起点,求每个点到最近起点的距离 | 多源 BFS | 全部源点距离 0 入队,一次泛洪 |
| 边权只有 0 和 1 | 0-1 BFS(deque:0 边插队头,1 边插队尾) | 维持队列单调性 |
| 边权非负、不全相等 | Dijkstra | FIFO 顺序不再等于距离顺序,需要优先队列 |
| 只问连通性/可达性(岛屿数量、flood fill) | DFS 或 BFS 均可 | 只关心"到没到",不关心"多远" |
| 枚举所有路径、回溯、拓扑排序、环检测 | DFS | 需要的恰恰是"沿路径深入"的顺序 |

判断口诀:**答案里出现"最短/最少/最近"且边权相等,闭眼 BFS;只问"能不能/有多少个连通块",DFS 更顺手;要枚举路径本身,只能 DFS。**
