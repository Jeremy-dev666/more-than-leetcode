# 背包计数的循环顺序 / Knapsack Loop Order (组合数 vs 排列数)

> **一句话 / TL;DR**：计数类背包中，**外层物品 = 组合数**（物品的相对顺序被枚举顺序固定死），**外层容量 = 排列数**（每个 `dp[i]` 都重新尝试所有物品作为「最后一步」）。

## 何时用 / When to use

触发信号：

- 题目问「凑出 target 有**多少种方式**」（计数，不是最值/可行性）
- 需要先判断：`(1,3)` 和 `(3,1)` 算一种还是两种？
  - 算一种（不区分顺序）→ 组合数 → 外层物品
  - 算两种（区分顺序）→ 排列数 → 外层容量

## 核心思想 / Core idea

两种循环顺序对应两种「计数的分类方式」：

**外层物品（组合数）**：物品的选择顺序被枚举顺序固定死了——先把物品 1 的所有贡献算完，再考虑物品 2。于是任何一个组合只会以「物品编号从小到大」这一种形态被统计，`(1,3)` 和 `(3,1)` 只算一次。等价的状态定义：`dp[i][j]` = 只用前 i 种物品凑出 j 的方案数。

**外层容量（排列数）**：每凑出一个 `dp[i]`，都重新尝试用**所有**物品作为「最后一步」：`dp[i] = Σ dp[i - num]`。这是按「最后用的物品是谁」分类——`(1,3)` 的最后一步是 3，`(3,1)` 的最后一步是 1，属于不同类，分别计数。等价的状态定义：`dp[i]` = 凑出 i 的**序列**数。

## 模板代码 / Template

```python
# 组合数(LC 518 Coin Change II):(1,3) 和 (3,1) 算一种
def combinations(nums, target):
    dp = [0] * (target + 1)
    dp[0] = 1                      # 凑出 0:什么都不选,1 种
    for num in nums:               # 外层物品:顺序被固定死
        for i in range(num, target + 1):   # 完全背包 → 正序
            dp[i] += dp[i - num]
    return dp[target]

# 排列数(LC 377 Combination Sum IV):(1,3) 和 (3,1) 算两种
def permutations(nums, target):
    dp = [0] * (target + 1)
    dp[0] = 1
    for i in range(1, target + 1): # 外层容量
        for num in nums:           # 内层物品:每个 dp[i] 都尝试所有「最后一步」
            if i >= num:
                dp[i] += dp[i - num]
    return dp[target]
```

## 变体 / Variants

| 问题类型 | 循环顺序 | 典型题 |
|---|---|---|
| 组合计数(完全背包) | 外层物品，容量正序 | 518 |
| 排列计数(完全背包) | 外层容量，内层物品 | 377, 70(物品={1,2}) |
| 排列型可达性(bool) | 外层容量，内层物品(单词) | 139 |
| 求最值(min/max) | **两种都对**——最优解与顺序无关 | 322 |
| 组合计数(0/1 背包) | 外层物品，容量**倒序** | 494 |

- LC 70 爬楼梯本质就是 `nums=[1,2]` 的排列计数——`(1,2)` 和 `(2,1)` 是两种爬法。
- LC 322 求最少硬币数：一个组合的所有排列硬币数相同，取 min 时重复计数无所谓，所以两种循环顺序都能得到正确答案（但计数题就会错）。

## 易错点 / Pitfalls

- **这套「交换循环」的戏法只适用于完全背包**（物品可重复使用）。0/1 背包（每个物品最多一次）如果外层容量、内层物品，就无法保证「每个物品只用一次」——同一物品会在不同的 `dp[i]` 处被反复使用。0/1 背包的排列计数不能靠交换循环解决。
- 组合数写法降到一维后，完全背包容量**正序**（要复用本轮新值）、0/1 背包容量**倒序**（防止复用），方向判据见 [DP 遍历方向](./dp-traversal-order.md)。
- `dp[0] = 1` 不是「凑出 0 有 1 枚硬币」，而是「空选法算 1 种方案」——它是所有计数的乘法起点，漏了整个 dp 全 0。
- 先问清「顺序算不算不同方案」再动手：题面说 combination 不代表就是组合数（LC 377 题名叫 Combination Sum 实际求排列数）。
