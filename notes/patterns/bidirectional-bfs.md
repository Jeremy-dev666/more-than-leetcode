# 双向 BFS:从起点和终点同时搜，在中间相遇

> 起因:LeetCode 752 (Open the Lock)。转密码锁求最少步数,标准 BFS 能过,但这题的结构——**起点和终点都明确、操作可逆**——恰好是双向 BFS 的教科书场景。
> 核心不是"两个 BFS 轮流跑"这个写法,而是背后的**指数减半**思想:meet in the middle。

## 一句话结论

**单向 BFS 的搜索量是 `b^d`,双向 BFS 是 `2·b^(d/2)`——把指数砍半,不是把常数砍半。**
`b` 是分支因子(每个状态能扩展出几个邻居),`d` 是最短路长度。从两头各搜一半深度,两棵搜索树在中间碰头,碰头节点两侧距离之和就是答案。

直觉图像:BFS 的搜索范围是一个以起点为圆心、半径为 `d` 的"圆",面积 ∝ `b^d`;双向 BFS 是两个半径 `d/2` 的小圆,总面积 ∝ `2·b^(d/2)`。指数上差一半,规模上差的是平方根——`b^d` 对 `(b^(d/2))²`。

以 752 为例:`b = 8`(4 个转轮 × 正反两个方向),若最短路 `d = 12`,单向要摸到 `8^12 ≈ 7×10^10` 量级的搜索树,双向只要 `2×8^6 ≈ 5×10^5`。当然 752 的状态空间总共只有 `10^4` 个,单向 BFS 被状态数封顶也能过——**双向 BFS 真正的用武之地是状态空间大到装不下、只能靠"少走"取胜的题**(如 127 Word Ladder 的大词典、滑块拼图类)。752 是理解它的最小样例。

## 成立条件:不是所有 BFS 都能双向

双向 BFS 是有前提的,三条缺一不可:

1. **终点是一个明确的状态**(或有限几个)。反向搜索要有出发点。像 286 那种"求到最近的门的距离"、或"走到任意边界即成功"这类目标是**条件**而非**状态**的题,反向队列没法初始化——只能单向(或多源)BFS。
2. **边可逆**。反向搜索每一步问的是"谁能一步到我",这要求操作可以倒推。752 的操作是拨轮 ±1,天然对称:`A` 能一步到 `B` ⟺ `B` 能一步到 `A`,所以反向搜索直接复用正向的邻居函数。若操作不可逆(有向图),反向扩展必须换成"逆操作",写不出逆操作就用不了双向。
3. **邻居可枚举**。这点 BFS 本来就要求,列在这里是提醒:双向 BFS 处理的通常是**隐式图**——状态空间由规则定义(拨一下轮子、换一个字母),而不是给好的邻接表。识别出"这是个状态图最短路问题"本身就是第一步。

## 实现要点:四个决定对错和快慢的细节

以 752 的实现([code](../../0752-open-the-lock/))为骨架:

```python
def bfs(s, t, dead):
    d1, d2 = deque([s]), deque([t])
    m1, m2 = {s: 0}, {t: 0}      # 距离表,同时兼任 visited

    while d1 and d2:              # 任何一边搜空 = 不连通,提前结束
        if len(d1) <= len(d2):    # 永远扩展更小的一侧
            res = update(d1, m1, m2, dead)
        else:
            res = update(d2, m2, m1, dead)
        if res != -1:
            return res
    return -1

def update(dq, cur, other, dead):
    for _ in range(len(dq)):      # 一次恰好扩展一整层
        poll = dq.popleft()
        step = cur[poll]
        for new_str in neighbors(poll):
            if new_str in dead or new_str in cur:
                continue
            if new_str in other:  # 在对面出现过 = 两棵树相遇
                return step + 1 + other[new_str]
            dq.append(new_str)
            cur[new_str] = step + 1
    return -1
```

### 1. 相遇判定在「生成邻居时」做,答案是两侧距离之和

相遇的本质:某个状态 `v` 同时被两棵搜索树发现,那么 `起点→v` 走 `m1[v]` 步、`v→终点` 走 `m2[v]` 步,拼起来就是一条完整路径。生成新状态时先查它在不在对面的距离表里,在就立刻返回 `step + 1 + other[v]`——这里 `step + 1` 就是它在本侧的距离,`other[v]` 是对面早已定案的距离(BFS 第一次发现即最短,见 [BFS vs DFS 最短路](./bfs-vs-dfs-shortest-path.md) 的分层证明,双向的两棵树各自都满足这条性质)。

### 2. 必须整层整层地扩展

`update` 里 `for _ in range(len(dq))` 锁定了当前层的节点数,一次处理完一整层才交还控制权。这是**正确性**要求,不是风格问题:两棵树相遇时答案取的是"两侧层数之和",只有双方都按层推进,第一次相遇才保证发生在层数之和最小的时刻。如果一侧扩展到一半就切换,层与层的边界被打乱,先碰上的可能是一条更长的路径。

### 3. 每次扩展更小的一侧——贪心平衡两棵树

`len(d1) <= len(d2)` 这个比较是纯粹的**性能**优化:总工作量 ≈ 两棵树扩展过的节点数之和,而每扩展一层,该侧下一层的规模乘上 `b`。让小的一侧先长,等价于始终压制增长更凶的那棵树,把两棵树的规模维持在同一量级——两个 `b^(d/2)` 的和,远小于一个 `b^(d-k)` 加一个 `b^k` 的失衡组合(极端失衡就退化回单向 BFS)。

这也顺带处理了"终点周围全是死锁"这类不对称局面:哪边被死锁掐得只剩几个节点,哪边就被优先推进,很快搜空并触发 `while d1 and d2` 的不连通判定,不用等另一边泛洪完整个状态空间。

### 4. 距离表兼任 visited,和 286 的 INF 判断同一个道理

`m1`/`m2` 一个字典干两件事:查过没有(键存在性)+ 走了几步(值)。能这么省的前提还是"第一次发现即最短"——写入一次永不更新。注意**两个方向的 visited 必须分开**:一个状态被正向访问过,不代表反向不需要它(恰恰相反,反向碰到它才叫相遇)。

## 易错点

- **起点 == 终点要特判返回 0**,且要在起点入死锁集判定之前/之后想清楚顺序(752 里 `"0000"` 本身可能在 deadends 里,返回 -1)。
- **忘记逐层扩展**:图方便写成"每次 pop 一个节点、看哪边队列短就 pop 哪边",相遇时刻的层数关系就不再有保证,可能返回偏大的答案。
- **误用于目标不明确的题**:目标是"满足某条件的任意状态"时反向没有出发点,强行枚举所有满足条件的状态塞进反向队列,可能比单向还慢(除非目标状态很少——那其实是多源 BFS 的镜像用法)。
- **有向操作直接复用正向邻居函数**:反向搜索的邻居是"逆操作"的结果,752 因为 ±1 对称才侥幸相同,换题前先确认可逆性。
- **返回值拼接漏加 1**:`step + other[v]` 少算了 `poll → v` 这条边,正确是 `step + 1 + other[v]`。

## 选型速查

| 问题特征 | 工具 | 原因 |
|---|---|---|
| 起点、终点都明确 + 操作可逆 + 状态空间大 | 双向 BFS | 指数减半 `b^d → 2·b^(d/2)` |
| 终点是条件不是状态 / 多个起点 | 单向(多源)BFS | 反向无从下手 |
| 状态空间小(≤10^5 量级) | 单向 BFS 通常够用 | 被状态总数封顶,双向只是锦上添花 |
| 起点终点明确但边权不等 | 双向 Dijkstra / A* | 同样的 meet-in-the-middle 思想,终止条件更微妙 |

触发信号:题面同时给出**初始状态**和**目标状态**,操作是对称的(±1、换一个字母、交换两个位置),而状态空间是指数级的(每位 10 种 × 4 位、单词长度 × 26)——看到这个组合就该想双向。

更广的视角:双向 BFS 是 **meet in the middle** 思想在图搜索上的实例——把一个深度 `d` 的问题拆成两个深度 `d/2` 的子问题,在中间对接。同一思想在枚举里的化身是"折半枚举子集"(把 `2^n` 变成 `2·2^(n/2)` + 哈希对接),识别出这层同构,两个套路就是一个套路。
